Why pixelpress

A press,
not a pipeline.

Most image tools make you choose between one file at a time and a wall of configuration. pixelpress is built for the whole folder: sensible defaults, explicit options, and output that is ready to ship.

01 / BULK

Point at the folder.

Quoted globs, recursive trees, include/exclude filters, symlinks, and collision detection. One command handles the whole asset directory.

"assets/**/*.{jpg,png}" -o dist -r
02 / RESPONSIVE

Every size you ship.

Responsive width sets, never upscaled. Hash filenames, prefixes, suffixes, and a manifest with ready-to-use srcset strings.

-w 480,960,1920 --hash --manifest images.json
03 / FRAMES

Animation survives.

Animated GIF and WebP inputs keep their frames in WebP output, including resized widths. Static formats fall back to the first frame.

-f webp --preset web
04 / BUDGETS

“Smaller than 120 KB.”

Set a per-variant byte budget and pixelpress searches quality down until it fits. If it cannot, the file fails loudly instead of shipping oversized.

--max-bytes 120kb -q 90
05 / REPEAT RUNS

A cache with a broom.

Cached by input mtime + option fingerprint. --prune deletes outputs no longer produced and removes empty directories, without touching inputs.

--cache --prune --watch
06 / SAFETY

No half-files.

Every image, manifest, report, and cache file is written to a temp file and renamed. A failed multi-format run rolls back newly created outputs.

atomic writes · rollback · guarded clean

The whole job

From source
to shipping.

Gather, transform, encode, and hand off. Nothing hides behind a build plugin you have to install first.

01Gather

Files, folders, globs, filters, symlinks. Mirror the tree or flatten it.

02Transform

Resize, crop, rotate, trim, extend, blur, sharpen, tint, grayscale.

03Encode

AVIF, WebP, JPEG, PNG. Per-format quality, effort, lossless, budgets.

04Ship

Manifest + srcset, <picture>, LQIP, HTML report, or stdout.

Repeated runs

Run it once.
Run it forever.

The cache lives outside your deployable output. The fingerprint covers quality, widths, transforms, and output paths, so changing an option invalidates exactly what it should.

--prune cleans up deleted sources and retired formats. Failed files keep their old outputs. --watch re-runs with the same cache and prune settings.

Cache, prune, watch →
terminal
# First run
pixelpress photos -o dist -r

# Second run: unchanged files are reused
pixelpress photos -o dist -r

# Clean retired sizes and formats
pixelpress photos -o dist -r --prune

# Keep going while you work
pixelpress photos -o dist -r --watch
node · optimize.js
import { optimize } from 'pixelpress';

const report = await optimize(
  ['public/images/**/*.{jpg,png}'],
  {
    outDir: 'dist/images',
    preset: 'web',
    widths: [480, 960, 1920],
    cache: true,
    prune: true,
  },
);

console.log(report.totals.savedPercent);
CLI + API

The shell and
the server.

The CLI is a thin surface over the same engine. If it works in your terminal, it works from Node — including transforms, budgets, cache, and failure reporting.

One image through a pipe? --stdout. A whole asset tree? A glob. Need the result in your build? The manifest has paths, bytes, dimensions, quality, and srcset.
